GAMES PLAYBOOK  (started 2026-11-11)
Read this before creating or rebuilding any game in the UI Snippets "Games" category.
Everything here came from building Rhythm Tap, Pong, Snake, Switchyard, Mini Sudoku and Battleship, plus ChatGPT's advice.

------------------------------------------------------------
1. WHAT CHATGPT SAID ABOUT GAMES (kept for reference)
------------------------------------------------------------
Shared by Puneet on 2026-11-11 (a screenshot of one point; the other points were not shared):

  "3. Measure actual engagement. This is probably your biggest opportunity. Track:
     - Game preview opened.
     - Game started.
     - Game completed.
     - Play again clicked.
     - Session duration.
     - Returning players."

How we plan to use it (not built yet, see SUGGESTIONS-UI-SNIPPETS.html "Measure game engagement"):
  - Google Analytics is already on; the missing piece is custom events.
  - Games run inside a sandboxed preview iframe, so one shared "event bridge" is needed: the game posts a message to the
    page (window.parent.postMessage), the page forwards it to gtag. Same channel can carry the storage bridge (section 4).
  - No game change needed: preview opened (page view), started (first key press / pointer press in the iframe), session length.
  - One line per game: completed and play again, e.g. sendGameEvent('complete', { level, stars }); it must do nothing outside the site.
  - Returning players: GA's new vs returning report; the games' own localStorage also tells them.
  - Anonymous only, respect the cookie banner (send nothing if analytics are declined), keep the privacy policy in step with ANALYTICS_NAMES.
  - Use the numbers to choose which game gets the next rebuild instead of guessing.
When designing a new game, build it so these events are easy to add: a clear "start" moment, a clear "complete / game over"
moment, and one "play again / next level" button.

2. THE RECIPE THAT WORKED (what makes a game worth coming back to)
------------------------------------------------------------
  - LEVELS AS DATA: one array (name, size, speed, rules, par). Tiers of 3 to 6 levels. Adding a level = adding a row.
  - SEEDED GENERATORS (mulberry32): level i always uses the same seed, so every player gets the same puzzle. Reject bad layouts and
    try the next seed. Validate with a solver or BFS (Sudoku: exactly one solution; Switchyard: every layout connected).
  - STARS + UNLOCKS: 1 to 3 stars per level (mistakes, hints, par time or shots), the next level unlocks with 1 star, star total on the menu.
  - DAILY CHALLENGE + STREAK + "Copy result" share line: date-seeded, same for everyone, streak resets after a missed day.
  - LIVES / MISSES (3), HINTS THAT TEACH (explain why in words), PENCIL NOTES / UNDO where the game has them.
  - DIFFICULTY RAMP inside a level too (faster, shorter gaps), and a clear reason to retry (par, stars, best time, best shots).
  - GAME FEEL: sound with a Web Audio synth (tone() and a noise() helper, no files), particles, screen shake, pop/wave animations,
    confetti on a win, animated star reveal, floating text, glow. A demo or autopilot running behind the menu makes it look alive.
  - PAUSE (Space or P) and auto-pause when the tab is hidden. Keyboard AND pointer input. Never hijack Ctrl/Cmd shortcuts, ignore key repeat.
  - A weapon / power-up that costs a choice (Pong orbs, Battleship sonar and cross strike) is more fun than a free bonus.
  - Opponents: make them beatable on purpose and fair (no cheating). Give a skill ladder (Battleship AI averages 62 / 52 / 49 / 44 shots).
  - Use the width: wide games (Switchyard, Battleship) fill the preview area; narrow ones fit-to-view.

3. TECHNICAL RULES
------------------------------------------------------------
  - Plain HTML/CSS/JS, no libraries, no image or audio files. The JS lives inside a template literal: NO backticks and NO ${ in the
    game code; write unicode as \\u2605 inside the snippet file; escape apostrophes in single-quoted SEO strings.
  - localStorage: wrap EVERY read and write in try/catch (sandboxed iframes throw SecurityError). Keep progress in one key per game
    (e.g. 'battleship-save-v1') as one JSON object.
  - Canvas games: scale the buffer by devicePixelRatio; use delta time (60fps units) so 120Hz screens are not twice as fast.
  - AudioContext only after a click (the Start / level button), every sound call in try/catch, a mute button.
  - Timers: bump a runId on every new game / menu visit so old setTimeouts do nothing.
  - Restarting a CSS animation: remove the class, force a reflow (void el.offsetWidth), add it again. Setting the same class string does nothing.
  - CSS pitfalls met: a selector like .stat b beats .lives (specificity, hearts turned white); a keyframe using background-color: inherit
    flashes the PARENT's colour; hidden attribute loses to display:flex.
  - FIT TO VIEW: the preview area can be short. Pattern: outer .xx-fit takes the scaled size, inner .xx-wrap is laid out at its natural
    size and shrunk with transform: scale(k), k = min(1, availW/naturalW, availH/naturalH), floor 0.4, re-fit on resize with
    ResizeObserver. On narrow screens (< ~760px) stack the layout and let the page scroll instead. (Mini Sudoku and Battleship have it;
    Snake, Pong, Switchyard and Rhythm Tap do not yet.)
  - The preview iframe uses sandbox="allow-scripts allow-forms" (no allow-same-origin), so localStorage is BLOCKED there: on the site the
    saves do not persist yet. Planned fix: a storage bridge over postMessage (parent keeps the data under a per-game key and injects it
    into the iframe at load); do NOT add allow-same-origin (My Code runs visitors' own code in the same iframe).
  - Overlays (menu, result) sit inside the panel with position:absolute; the same panel scales with the game.

4. SITE CHECKLIST FOR A NEW OR REBUILT GAME
------------------------------------------------------------
  - File: src/components/UiSnippetsTool/snippets/<id>.js (category 'games'); bump lastmod.
  - New game only: import + add to SNIPPETS in snippets.js; node scripts/generate-snippet-search-index.mjs (also after a TITLE change);
    SNIPPET_COUNT in src/lib/snippet-count.js; ONE line in src/lib/snippet-tag-map.js (never run the full tag generator: it re-tags ~50 games).
  - EVERY game is Patreon-only: add the id to PATREON_GAME_IDS (src/lib/patreon-settings.js) and fix the count in the comment above it.
  - Give it a type in src/lib/game-genres.js (Arcade, Puzzle, Coding, Board & Card, Skill & Reflex, Brain & Memory, Word, Physics, Luck & Fun).
  - SEO title 50-60 characters, description 150-160 (show the counts); rewrite about, howToUse, features, useCases, FAQs, aiPrompt.paragraph AND
    aiPrompt.prompt so they describe the game as it is now.
  - Preview image: capture a GAMEPLAY frame (not the start screen) with a temporary Playwright script, open the png and look at it, delete the script.
  - Test the game logic with a bot in headless Chromium (generated page, not the user's server): all levels solvable, win / lose / unlock / daily
    paths, no page errors, storage blocked case. Fix what the screenshot shows.
  - Add a dated line to 05-ADVISOR-LOG.txt; mark the idea in SUGGESTIONS-UI-SNIPPETS.html; do not deploy until asked.
  - Small UI changes (nav, sidebar, labels): edit, syntax-check, say it is untested. Puneet said "do not test" on 2026-11-11.

6. MORE LESSONS (added 2026-11-11, Color Sort + Checkers)
------------------------------------------------------------
  - Generate puzzles BACKWARDS from the solved state with inverse moves (Color Sort): always solvable, and a seed makes it the same for everyone.
    A scramble length is a poor par: take the length of a real solver solution (a greedy best-first search with a heap is enough) as par.
  - A turn can be a whole SEQUENCE (checkers multi-jump): generate complete sequences once and let the UI, the AI and the move log share them;
    in the UI only show the squares that continue a legal sequence and refuse other clicks mid-chain.
  - Computer opponents: negamax + alpha-beta + iterative deepening + a time cap + a capture extension; weaker levels = lower depth AND random noise
    added to root move scores (a shallow horizon alone plays oddly, noise plays like a distracted human). Test strength with engine-vs-engine games
    in both seats (depth 6 beat depth 2 in 5 of 6, depth 2 beat random 6 of 6).
  - CSS content escapes use \265B (hex), NOT ♛; inside the snippet template literal that is written \265B.
  - Seeded daily starts must be checked for fairness (no capture on offer, equal material) or the "same for everyone" game is unequal.
  - Persistent piece elements moved with CSS transitions (left/top in %) beat re-rendering the board on every click; remove captured pieces
    with a short scale/fade class, then delete the element.
  - A fixed segment height (flex: 0 0 Npx) stops liquid layers stretching in part-filled tubes.
  - GENERATE AND VERIFY (Minesweeper): place mines at random, run the solver on the whole board, keep it only if the solver clears it (no 50/50
    guesses ever); reveal an opening at the start so there is no first-click guess either. Use the SAME solver for hints and explain the
    deduction in words, highlighting the clue cells and the target cell. Prove it with a bot that uses only the solver: it must win every level.
  - When a render function rewrites className, keep one-shot animation classes (win, hint highlights) or they vanish on the next render.
  - Timers: stop counting while the tab is hidden (reset lastTick on hidden), and start the clock on the first player action, not at level load.
  - Typing-test lessons: WPM = correct chars / 5 / minutes (only correct words count), accuracy = per KEYSTROKE and never reduced by Backspace; use a
    word-based model (Space commits a word) not strict position matching, or one skipped letter ruins the rest; repaint only the current word.
    Record per-letter attempts/misses: it powers a Weak keys mode, a keys-to-practise list and a tinted on-screen keyboard (a reason to return).
  - If a view has dead space, fill it with something that teaches or motivates (the on-screen keyboard) instead of shrinking the panel.
  - ONE RULES INTERFACE (Tic-Tac-Toe): give every game type the same functions (moves, play, winner, evaluate) and one search serves classic, big boards
    and Ultimate, plus hints and a generated daily puzzle. Perfect-play levels need an objective a human can meet (a draw passes).
  - A solver also makes the daily content: random position -> keep it only if the solver says it has a forced win of the wanted length.
  - One-shot CSS animation classes must survive re-renders for the animation's duration (store a timestamp per cell), not just the render that added them.

2048 lesson: keep tiles as persistent elements with ids and animate via transform; redrawing every move makes tiles jump. Merge flag per move prevents 2,2,4 -> 8.

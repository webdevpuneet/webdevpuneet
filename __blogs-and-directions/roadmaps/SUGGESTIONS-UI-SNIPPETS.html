Rule for what gets added: an idea goes here only if it fills a real gap (something visitors look for that the site does not have, or a workaround a current template forces). Ideas for other areas live in their own files; start from the Suggestions index.

Virtual piano: next-level ideas (after the 2026-11-07 rebuild)

Suggested

Added 2026-11-07 · the rebuild is done (25 keys, 4 voices, reverb, chord detection, recorder, MIDI); these are the next steps

Ordered by effect on traffic and shares: (1) Learn a song mode, falling notes that guide the player through a simple melody such as Ode to Joy, plus a scoring pass; (2) scale highlighter, a dropdown that tints the keys of C major, A minor or pentatonic; (3) share a recording as a URL (events encoded in the hash) so a visitor can send a tune; (4) ear-training quiz that plays a note, interval or chord and asks for its name; (5) tempo grid and quantise with the audio metronome; (6) sampled piano option with decodeAudioData for a realistic sound; (7) an AnalyserNode oscilloscope next to the bars. Measure game engagement (ChatGPT's suggestion, 2026-11-11)

Suggested

Added 2026-11-11 · not started · wanted events: game preview opened, game started, game completed, play again clicked, session duration, returning players

Google Analytics is already on (Clarity and Statcounter are off, Ahrefs Web Analytics is on), so no new service is needed; the missing piece is custom events. The games run inside the snippet preview iframe, so the plan is one small shared bridge: the preview wrapper posts a message to the page, and the page forwards it to gtag as an event. Cheap events with no change to any game: preview opened (the page view of /ui-snippets/<game>/), started (first key press or pointer press inside the iframe), session duration (time from started to leaving the page, sent on pagehide). Needs a line in each game: completed and play again, because only the game knows when it ends; add a shared helper such as sendGameEvent('complete', { level, stars }) that does nothing outside the site, and call it from the games that matter most first (Switchyard, Snake, Mini Sudoku, Pong). Returning players come free from GA's new/returning users report, and the new games also save progress in localStorage, so a "returning" check by the game itself is possible without cookies. Keep it anonymous (no names, no ids), keep the privacy policy wording in step with ANALYTICS_NAMES, and note that visitors who decline analytics must send nothing. Use it to decide which games get the next rebuild (the 2026-11-11 rebuilds were chosen by guess).

New wide game: train switch puzzle ("Switchyard")

Built

Added 2026-11-11 · BUILT 2026-11-11 as /ui-snippets/switchyard-train-puzzle-game/ (Games, Patreon-only code) · asked for: unique, fun, levels, uses almost the full preview width, a reason to come back

Coloured trains enter on the left of a wide landscape board and travel right along branching tracks. The player taps junctions to flip them so each train reaches the station of its own colour. The play field is the width itself, so the canvas should scale to the container (about 2.4:1), unlike the narrow Snake, Pong and Rhythm Tap boards. Levels: about 20, adding junctions, more colours, faster trains, tunnels that hide a train, and crossings where two trains crash; 1 to 3 stars per level, unlocked one by one. Come back: a Daily Route seeded by the date (the same board for everyone), a day streak, a star total, and a copyable result line to share. Alternates considered: a typing game where CSS property names ride a conveyor across the full width (fits the learning position), and a bridge builder across a wide canyon. Candidate names: Switchyard, Junction Rush, Color Line Express, Track Switch, Signal Box, Rush Hour Rails. Patreon-only code like the other games; follow the snippet update checklist.

    in the sandbox): Swiper, SortableJS, Anime.js, Splide, Muuri, Matter.js,
    p5.js, PixiJS, Konva, Fabric.js, Interact.js, CountUp/Odometer.

==========================================================
PART 3 — AUTHORING CONSTRAINTS THAT WILL BITE YOU
==========================================================
Every one of these caused a real bug in the existing library. Check them
before writing a new snippet.

SANDBOX
  Preview runs in <iframe sandbox="allow-scripts allow-forms"> — deliberately
  NO allow-same-origin. Consequences:
    * localStorage / sessionStorage THROW a SecurityError on access. They do
      not fail quietly. Always wrap in try/catch and degrade gracefully.
      (This broke simon-sequence-game: best score permanently stuck at 0.)
    * Any uncaught error from a CDN script reports only as "Script error."
      with no line number. Debug by popping the demo out to its own tab.
    * The iframe has an opaque origin — cookies, IndexedDB and the
      permissions-gated APIs behave differently than on a normal page.

CDN URLS — VERIFY BEFORE SHIPPING
  Four separate snippets shipped broken CDN URLs. Always curl the URL and
  confirm the global name before writing code against it.
    * Case matters on cdnjs: swup/4.4.1/Swup.umd.js works,
      swup.umd.js is a 404.
    * cdnjs does not host everything. barba.js on cdnjs tops out at the old
      v1; the modern rewrite is @barba/core on jsDelivr. locomotive-scroll
      isn't on cdnjs at all.
    * Version determines the API. popmotion@8 has no animate() export at
      all — the unified animate({keyframes,type}) API only exists from v10.
    * Confirm the UMD global (window.popmotion, window.LocomotiveScroll,
      window.Swup) matches exactly what the snippet code calls.

ANIMATION GOTCHAS ALREADY HIT
  * GSAP: give filter/opacity an explicit CSS starting value. Without one,
    gsap.to(el,{filter:'brightness(0.6)'}) interpolates from brightness(0),
    i.e. through full black. (scroll-sticky-stack)
  * GSAP ScrollTrigger: a position:sticky element used AS the trigger can
    never reach 'top top' — it freezes at its sticky offset, so the scrub
    overshoots past 1 and extrapolates past your end values.
  * ScrollTrigger position strings accept %, px and keywords — NOT vh.
    'top 14vh' is silently parsed as 14 pixels.
  * Extending a ScrollTrigger's `end` does NOT add a hold at the end; it
    just slows everything down proportionally. To hold, add a no-op tween
    to the timeline itself.
  * Matter.js: use Body.setVelocity for a one-shot launch, not applyForce —
    applyForce divides by mass, so small randomized bodies fly off screen.
  * Clearing only `style.transition` while leaving inline opacity/transform
    set means a later class can never take effect — inline always wins.

LAYOUT GOTCHAS ALREADY HIT
  * A position:relative wrapper inside a flex body stretches to full height
    by default, so an absolutely positioned dropdown using top:100% lands at
    the bottom of the viewport. Add align-self:flex-start.
  * Don't mix a CSS :hover reveal (opacity) with a JS visibility toggle on
    the same element — inline visibility:hidden silently wins forever.
  * If a container is overflow:auto, hide the scrollbar deliberately
    (scrollbar-width:none + ::-webkit-scrollbar{display:none}) — a raw
    scrollbar inside a phone mockup or code panel looks broken.
  * Horizontal-only scroll containers ignore the vertical mouse wheel.
    Translate deltaY to scrollLeft or desktop users think it's frozen.

GOTCHAS FROM THE 2026-09-24 BATCH (50 snippets)
  * A literal closing script tag ANYWHERE in a snippet's JS - even inside a string or a
    comment - ends the inline <script> in the preview early ("Invalid or unexpected token").
    Split it: '</scr' + 'ipt>'. Backticks and dollar-brace in snippet JS also break the
    template literal the snippet files are stored in - spell a backtick as String.fromCharCode(96).
  * Modern V8 no longer puts a character position in JSON.parse errors (it quotes a snippet
    of the text). Firefox and Safari differ again. Never scrape the message for a location -
    write a small validator that returns the offset (see codemirror-json-editor-validation-gutter).
  * Tabulator: the table builds asynchronously - use the tableBuilt event before any API call,
    and take match counts from the rows passed to dataFiltered (getDataCount('active') can be stale
    inside that event).
  * noUiSlider vertical handles are positioned with `bottom`, not `top` - an override that sets
    `top` displaces the handle by the full track height. A vertical slider needs an explicit CSS height.
  * Interact.js: interact.snappers.grid is anchored to the PAGE, not the container, and
    offset:'parent' did not fix it in 1.10.27. Round a running raw position by hand instead.
    Do not re-append a node in a 'down' handler - it can cancel the interaction; bump z-index.
  * Prism line-numbers/line-highlight: do not add offsets to .line-numbers-rows or .line-highlight;
    the plugins already measure the <code> element. The theme's own line-height on <code> must
    match the <pre> or the gutter drifts.
  * Medium-zoom: getZoomedImage() is the original thumbnail; the hi-res swap is a SECOND
    .medium-zoom-image--opened <img> in <body>. Read the largest natural width among them.
  * Swiper thumbs: create the thumbnails swiper first. Swiper fade: crossFade:true or slides overlap.
    Swiper cards effect: dragging moves through the deck like a normal slider - it is not a
    left/right decision gesture.
  * Sortable: filter alone does not stop other rows displacing a locked one - add onMove. filter also
    swallows clicks unless preventOnFilter:false. An empty drop target needs a real height.
  * Fuse.js multiplies per-key scores, so an exact hit in a low-weight key can outrank a near-exact
    hit in a high-weight one. Test weights against real queries.
  * The preview iframe has an opaque origin: localStorage throws, alert() is blocked (no allow-modals).

GOTCHAS FROM THE 2026-09-25 BATCH (50 snippets)
  * html2canvas FAILS inside the sandboxed preview (opaque origin). Use html-to-image
    (window.htmlToImage) instead, and inject Google Fonts with a <link crossOrigin="anonymous">
    from JS so the fonts can be embedded in the export.
  * Downloads (a[download]) do nothing in the sandbox - always show the result inline too
    (an <img>, an <iframe> of a blob PDF, or a textarea) so the preview proves it worked.
  * PDF.js 3.11 classic build works in the sandbox (fake worker). getDocument DETACHES the
    ArrayBuffer you pass - give it bytes.slice(0) if you still need the bytes (e.g. for pdf-lib).
  * Embla v8: there is no clickAllowed() - suppress clicks after a drag with a capture-phase
    click listener. autoplay:timerset fires before your listeners attach, so start any progress
    bar manually after init. Plugins are UMD globals: EmblaCarouselAutoplay, ...AutoScroll, ...Fade.
  * ApexCharts sparklines: create ALL card DOM first, then the charts, or early charts measure
    a wider container and overflow.
  * SheetJS: read with cellNF:true to keep number formats; use cdn.sheetjs.com (xlsx-0.20.3),
    the npm package is stale.
  * Turndown: addRule() unshifts, so a LATER rule wins over an earlier one for the same node.
  * Matter.js: MouseConstraint swallows the wheel - remove its listeners
    (['mousewheel','DOMMouseScroll','wheel'] with mouse.mousewheel) so the page scrolls.
    Set Render pixelRatio to devicePixelRatio and ctx.scale(pr,pr) in afterRender drawing.
    Parts of one rig (car, jelly) need a shared Body.nextGroup(true). For a scrolling camera
    use hasBounds + render.bounds and setTransform(pr,0,0,pr,-minX*pr,-minY*pr) for custom
    drawing. Don't spawn bodies above a ceiling wall. Carrying a swinging block's sideways
    velocity into a long fall makes it drift ~150px - feels unfair in a stacking game.
  * Plinko fairness: pegs alone skew the distribution; add guard walls parallel to the peg
    edge and a random left/right kick on peg collisions to get a true binomial curve.

==========================================================
PART 7 — WORKING RULES
==========================================================

1. BUILD IN CLUSTERS OF 8-12, NOT ONES AND TWOS.
   The library's main structural weakness is 45 orphaned libraries. A
   cluster ranks, cross-links and justifies a "Built with X" filter page.
   A single snippet does none of that.

2. NAME FOR THE SEARCH, NOT THE LIBRARY.
   "Store Locator Map with Search" beats "Leaflet Demo 3". Put the library
   in the cdnUrls and the about/description, where the Built-with filter
   picks it up.

3. VERIFY THE CDN URL AND GLOBAL BEFORE WRITING CODE.
   curl the URL, confirm the global name, confirm the version's API. Four
   shipped snippets were broken by skipping this.

4. ASSUME NO SAME-ORIGIN.
   try/catch every storage access. Never rely on cookies or IndexedDB.

5. NO SNIPPET SHOULD SCROLL INTERNALLY UNLESS SCROLLING IS THE POINT.
   Demos are embedded in blog iframes at a fixed height — content hidden
   below an inner scrollbar is content nobody sees.

6. EVERY SNIPPET NEEDS ITS PREVIEW PNG AND TAG-MAP ENTRY.
   Missing either one makes it invisible in the gallery and the sidebar.

7. PREFER PATTERNS WITH A REAL FAILURE MODE TO EXPLAIN.
   The strongest existing snippets document a gotcha (focus traps, stale
   closures, sticky-trigger math). That is what makes them worth linking
   to from a blog post.

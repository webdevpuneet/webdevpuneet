QUALITY BARS AND WORKING RULES
Last updated 2026-10-29

A-GRADE SEO (every new or changed page)
  - Title 50-60 characters, meta description 150-160, both unique across the site; primary keyword
    in both. Show the counts when proposing them.
  - Exactly one h1 on every exported page (page.js ensureH1 promotes the first heading on pages
    without one).
  - About text 300+ words with 5+ sub-headings that documents EVERY option and capability.
  - 2+ internal links that resolve (related sections, the website template that uses it, My Code).
  - 8 features, 3 reasons, 4 use cases (18-42 words each), 4 FAQs (answers 25-70 words), AI prompt.
  - Every image has alt text of 10+ characters; preview and share (og) images exist.
  - Structured data that parses (FAQPage, BreadcrumbList, CreativeWork; MusicEvent where relevant).
  - Sitemap, llms.txt and static routes come from the registries (scripts/postbuild.js).
  - The audit script used on 2026-10-27 checked 385 points; re-run the same checks for new work.

ACCESSIBILITY
  - Real buttons and links with labels; visible focus; reduced motion respected; content visible
    without JavaScript; keyboard paths for carousels, players and menus.

PERFORMANCE
  - Animate transform and opacity; load GSAP plugins only when used; lazy-load below-the-fold images.

TEMPLATES
  - Real industry copy, fictional brands, example links/emails use webdevpuneet.com (never yoursite.com).
  - Email templates: icons must be PNG images, never SVG.
  - Demos are noindex and link back to their template page.

UI SNIPPET UPDATE CHECKLIST (every time a snippet in src/components/UiSnippetsTool/snippets/ is redesigned or changed)
  Do ALL of these in the same pass, not just the code:
  1. Code: html / css / js in snippets/<id>.js; bump lastmod to today.
  2. SEO title 50-60 chars and description 150-160 chars (show the counts). Re-check them even if the title is unchanged.
  3. SEO text that describes the old design: about article, howToUse steps, features, useCases and FAQs must match the new
     behaviour. Search the file for stale words (old class names, old keyframes, removed features) and fix them.
  4. AI prompt: update BOTH aiPrompt.paragraph (suggested follow-ups must not offer what already exists) and
     aiPrompt.prompt (the requirements must describe the new design and behaviour).
  5. Preview image: re-capture with  node scripts/capture-snippet-previews.mjs <id>  (headless Chromium, allowed), then OPEN the
     png and check it. If the snippet has an entrance animation longer than 0.5s, the script's 500ms wait catches it half-drawn:
     use a temporary copy of the script with a longer waitForTimeout, and delete the copy afterwards.
  6. Syntax-check the edited file (import it with node) and print title / description lengths.
  7. Do not deploy unless asked; mention that live pages keep the old image until the next deploy.
  8. Add a dated line to 05-ADVISOR-LOG.txt (area: ui snippets).

WORKING RULES (from Puneet)
  - Never run builds or dev servers to test unless asked; headless Chromium (Playwright) is allowed.
  - Deploy only when asked: NEXT_DIST_DIR=.next-deploy npm run deploy, then Puneet extracts
    /tools.zip on the server and deletes it.
  - Demos: node scripts/export-website-demos.mjs, then node scripts/upload-demos.mjs (--preview first).
    The upload compares file size, so same-size edits are not re-sent.
  - New tools go in test mode first unless Puneet asks for live.
  - Blog drafts are rebranded to webdevpuneet.com; WordPress output is one <name>-wordpress.txt.
  - Read and update __directions/roadmaps/TEMPLATES-ROADMAP.html and SUGGESTIONS.html when working on templates.

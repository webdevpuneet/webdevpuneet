Vision

A free, editable website-building library that grows in three layers, each feeding the next:

  1. Visual assets (done): Email Templates (27) and Social Post Templates (34).
  2. Section Templates: complete, responsive page blocks (hero, features, pricing…) that people customise in the browser (text, images, brand colours, fonts) and export as HTML/CSS, a ZIP, React or Vue.
  3. Website Templates: full pages and sites built by stacking sections in a page builder. A website template is a saved stack of sections with sample content, so every new section makes the website templates better.

Users find us through Google and AI assistants, use everything free with no account, and never lose work: designs, images and fonts live in their browser (IndexedDB) and can be exported to a backup file and imported anywhere.

Principles (non-negotiable)

  • Editable, not just copyable. Every section has fields, image slots, toggles and theme tokens. This is what separates it from the UI Snippets library.
  • One shared theme. All sections read the same design tokens (colours, fonts, radius, width), so any combination looks like one website. This is the foundation of the page builder.
  • Responsive by container, not viewport. Sections use CSS container queries, so they adapt correctly in the editor preview, the page builder and the user's own site.
  • Never lose user data. Autosave, My designs, uploaded images and custom fonts in IndexedDB; one-file backup export and import that never overwrites.
  • Private. Everything runs in the browser; nothing is uploaded.
  • Free forever, no watermark.
  • SEO on every page. Same depth as the email and social templates: title 50–60 chars, description 150–160, keywords, long About, features, why, use cases (4 × 18–42 words), FAQs, schema, sitemaps, llms.txt.
  • Reuse before writing new code (see Architecture). No builds or dev servers to test; the user tests locally.

Section template shape

{
  id, name, version, category, tags, created, updated,
  seoTitle, seoDescription, description, bestFor: [..],
  groups:  [{ id, label, toggle? }],
  fields:  [{ key, group, label, type: 'text'|'textarea'|'url'|'image', value, hint?, upload? }],
  toggles: [{ key, label, value }],
  theme:   { …overrides of DEFAULT_THEME },      // the section's own default look
  html: `…data-edit="key" data-href="key" data-image="key" data-show="toggle"…`,
  css:  `.hx-… { … var(--st-brand) … @container st (max-width: 720px) { … } }`,

Bindings in section HTML

data-edit="key"Text field (rich text: *accent*, <b>, <i>, <br>, links).
data-href="key"Link field on an <a> (http/https/mailto/tel/# only).
data-image="key"Image field on an <img> (src set from upload or URL; placeholder when empty).
data-show="toggle"Element removed when the toggle is off.
data-show-if="key"Element removed when that field is empty (e.g. an optional second button).
data-bg="key"Background image from an image field.
data-optionalOn an <img data-image>: removed when empty instead of showing a placeholder.
data-list="key"Repeatable items from t.lists: the element's first child is the item template, rendered once per item; bindings inside read the item's own fields (they're renamed data-i-* after filling).
data-links="key"Empty <ul>/<ol>: one <li><a> per line written Label | URL (field type links).
data-set="attr:key;…"Sets attributes from fields (form action, input name/placeholder…); href/src/action through safeUrl; event attributes refused.
schema(state) (template)Returns structured data (e.g. FAQPage) that exported pages get as JSON-LD in <head>.
data-accordionAccordion list of details.st-acc; values single and first.
data-hide-if="key"Element removed when that field is NOT empty (a default suffix replaced by a plan's own price note).
behaviors: [...] (template)Interactive scripts from behaviors.js (now: billing, carousel with [data-carousel] / -prev / -next, marquee with [data-marquee] / ="reverse" / data-speed; next: accordion, menu, tabs, counter). Markup uses data-billing buttons, .st-bill-pill, .st-pm / .st-py.
data-icon="key"Empty element filled with an inline SVG icon (icon field, ids from icons.js).
data-lines="key"Empty <ul>/<ol>: one <li> per non-empty line (lines field).
data-anim-textHeading animated with the SplitText text effect (motion.text); kept in exports.
data-anim="item" / "media"Motion marker: text/buttons animate in a stagger (item); images/mockups use the media variant. Kept in exports (not stripped by clean).

Motion & JS libraries (GSAP is integral)

Animation is part of every section, not an add-on. Every new section, page-builder feature and website template must be designed with GSAP in mind and stay compatible with it.

How it works now

  • Library: GSAP 3.15.0 (all plugins free since 3.13) from cdnjs. GSAP_VERSION, GSAP_PLUGINS (all 19 plugins, cdnjs-verified) and gsapCdn(plugins) live in templates/meta.js; GSAP_CDN = core + ScrollTrigger. Versions are pinned; bump in one place.
  • Plugin loading: each section / effect declares the plugins it needs; exports load only those via gsapCdn() (core + ScrollTrigger always, dependencies such as CustomEase added automatically), so pages stay light.
  • Markers: sections mark elements with data-anim="item" or data-anim="media". Templates never contain their own animation code.
  • Presets: MOTION_PRESETS (none, fade-up, fade, slide, zoom) each give "from" vars for items and media; MOTION_SPEEDS scale duration. State: motion: { preset, speed }.
  • Runtime: motionScript(state) in render.js builds a small script: one ScrollTrigger per section, plays once at ~80% viewport, gsap.from() with stagger.
  • Progressive enhancement: content is visible by default; without JavaScript or when GSAP fails to load nothing is hidden. prefers-reduced-motion skips animation.
  • Editor: the preview is still while editing; ▶ Play animation replays it. Thumbnails, gallery cards and captured previews render with motion: false.
  • Exports: HTML/ZIP get the CDN <script> tags + runtime (motionTags); React/Vue get the runtime in an effect/mounted hook with the CDN URLs listed (snippetParts.cdnUrls); Fork to My Code adds GSAP as a CDN link.

Rules for compatibility

  1. Animate with transforms and opacity only (no layout properties), so container queries and the builder are unaffected.
  2. Scope every selector to the section root; never animate globally or use IDs.
  3. One ScrollTrigger per section; the page builder includes GSAP once and runs each section's setup, so stacking sections never loads GSAP twice.
  4. Kill and re-create triggers on re-render (builder reorder, React unmount) to avoid leaks.
  5. Animations must not hide content that is needed for SEO or screenshots.

Checklist for every new section

  1. Create templates/<id>.js (fields, toggles, theme, html, css with container queries; check a light and a dark preset).
  2. Add data-anim="item" / "media" markers and data-anim-text on the main heading; check every motion preset and text effect (and that the section looks complete with motion off).
  3. Repeating content (cards, plans, rows, steps) goes in lists with min/max and sensible defaults; icons via an icon field; bullet points via a lines field. Default art: generate with sharp (no text in images).
  4. SEO: seoTitle 50–60 and seoDescription 150–160 characters (check with node before saving).
  5. Interactive parts (switches, accordions, carousels) go in behaviors.js, never inline in a template: plain JS first, GSAP plugin animation on top, reduced-motion respected, scoped to each .st. Test clicks headless before calling it done.
  6. Re-capturing an existing preview needs --force: node scripts/capture-section-previews.mjs --force <id>.
  7. Register in templates/index.js.
  8. Add SEO entry in seo-content.js (all fields, lengths checked) and update the category intro in seo-categories.js.
  9. Run node scripts/capture-section-previews.mjs <id> and review the preview + OG image.
  10. Run node scripts/generate-template-nav.mjs (sidebar).
  11. Update this roadmap: catalogue row, checklist, change log.

2026-10-20Section templates are editable templates (fields, images, theme), not another snippet list.UI Snippets already covers copy-paste components; editing + branding is the gap.
2026-10-20Website templates = presets of a page builder that stacks sections.One system to maintain; every new section improves every website template.
2026-10-20Shared theme tokens as CSS custom properties (--st-*).Lets any mix of sections look like one site; makes the page builder possible.
2026-10-20Container queries (container: st / inline-size) instead of media queries.Sections respond to their own width in the editor, builder and user sites alike.
2026-10-20Uploaded images stored as Blobs in a separate asset store (email approach), not data URLs in state (social approach).Hero photos are large; keeps designs light and autosave fast.
2026-10-20GSAP (+ ScrollTrigger) is an integral motion layer for sections, the page builder and website templates; other JS libraries may be added only when GSAP has no equivalent (superseded by the all-plugins decision below), always pinned from cdnjs and included in exports.User request; animation is a big part of modern sites and GSAP is the industry standard. Markers + one runtime keep templates simple and stackable.
2026-10-20Use all GSAP plugins (SplitText, TextPlugin, ScrambleText, Flip, Draggable/Inertia, DrawSVG, MorphSVG, MotionPath, ScrollSmoother, Observer, custom eases, physics) to make the platform rich in text and element animation. Upgraded GSAP 3.12.5 → 3.15.0; GSAP plugins preferred over other libraries (e.g. ScrollSmoother over Lenis, Draggable over Swiper).User request. All plugins have been free since 3.13 and are on cdnjs; one library and one runtime keeps exports small and consistent.
2026-10-20The builder will let users create scroll-based section animations (scrub, pin, keyframe tracks, effect presets) visually — Phase 3b.User request; scroll-driven motion is a standout feature most free builders lack. Stored as JSON + one runtime so every export keeps working.
2026-10-20The page builder is its own tool at /website-builder/ (user's choice), separate from the section library URL.Targets "website builder" searches and reads as a product in its own right.
2026-10-20URL: /website-section-templates/ (user's choice). Code lives in components/SectionTemplates; images in public/images/section-templates/.Says exactly what it is and targets "website section templates" searches.

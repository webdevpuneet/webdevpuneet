---
name: SEO content must match search intent
description: When writing SEO content for any tool, think about WHY and HOW a user would search for it — satisfy the intent behind the keyword, not just list features
type: feedback
---

SEO content must be written from the perspective of what a user is actually searching for — their intent, their problem, and the words they would type. Feature-listing copy does not rank well because it does not match the language of search queries.

**Why:** Search engines rank pages that satisfy the searcher's intent. A user searching "how to test API in browser without postman" has a specific problem — the content must speak to that problem directly, not just say "this tool has a Send button". Intent-matching content converts better too.

**How to apply:**
- Before writing any SEO section, ask: what problem does this tool solve? What would a developer type into Google to find it?
- Think in terms of intent categories:
  - **Informational** ("how to generate curl from fetch", "what is jsonpath filter") — answer it directly in FAQs or body text
  - **Navigational/alternative** ("postman alternative browser", "insomnia without install") — address these explicitly in comparison sections
  - **Task/do** ("generate axios code from url", "test rest api online") — the about and how-to sections must describe doing the task, not just listing the feature
- Use the natural language a developer would type: "send api request from browser", "convert curl to python", "test graphql endpoint online"
- FAQs should be phrased as real questions users type, not polished product documentation titles
- Include the pain point: why is the user searching this? (e.g. "don't want to install Postman", "need to share a request with a teammate", "want to check what an API returns")
- Avoid writing SEO copy that reads like a changelog or feature announcement — write it as the answer to the question the user is asking

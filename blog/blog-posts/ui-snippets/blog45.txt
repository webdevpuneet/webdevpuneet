<h2>1. Bootstrap Diff Viewer</h2>

<p>A real line-level text diff using genuine longest-common-subsequence matching — added lines highlighted green, removed lines struck through red, and unchanged lines correctly recognized even between edits.</p>

<iframe src="https://fwdtools.com/ui-snippets/bootstrap-diff-viewer/embed/" style="width:100%;height:400px;border:0;border-radius:10px;overflow:hidden;" loading="lazy" title="Bootstrap Diff Viewer — Free HTML CSS JS Snippet by FWD Tools"></iframe>

<p><strong>How it works:</strong> a dynamic-programming table records the length of the longest matching subsequence between the remaining old and new lines from every position, built from the bottom-right corner upward. Walking that table forward turns the LCS lengths into an actual sequence of same/add/remove operations — comparing <code>dp[i+1][j]</code> against <code>dp[i][j+1]</code> at each mismatch decides whether a line was removed or inserted, always preserving the longer eventual match. That's what correctly identifies an unchanged line as unchanged even when the lines around it were edited.</p>

<p><strong>Best for:</strong> document and CMS revision comparisons, and configuration change review. <strong>Tip:</strong> pair with the version history panel elsewhere in this collection to show exactly what a restore would change before committing to it.</p>

<h2>5. Bootstrap Inline Table Cell Editing</h2>

<p>Click a Qty or price cell to edit it in place — Enter or clicking away saves a validated number, and Escape reverts, guarded against a subtle DOM-removal bug that could otherwise overwrite the cancel.</p>

<iframe src="https://fwdtools.com/ui-snippets/bootstrap-inline-table-cell-editing/embed/" style="width:100%;height:420px;border:0;border-radius:10px;overflow:hidden;" loading="lazy" title="Bootstrap Inline Table Cell Editing — Free HTML CSS JS Snippet by FWD Tools"></iframe>

<p><strong>How it works:</strong> Enter, blur, and Escape all funnel through one <code>commit(save)</code> function, guarded by a <code>committed</code> flag for a genuinely subtle reason — removing a focused input from the DOM (which re-rendering does) itself fires a native <code>blur</code> event on it. Without the guard, pressing Escape would discard an edit, re-render, and then that synthetic blur would immediately re-fire a save with the same stale value, silently undoing the cancel a moment later. A save is only applied when the parsed value is a valid non-negative number.</p>

<p><strong>Best for:</strong> inventory, pricing, and spreadsheet-style admin tables where a quick numeric correction shouldn't need a separate edit form. <strong>Tip:</strong> this is exactly the kind of race condition that's easy to miss in a homemade version and only shows up as an intermittent, hard-to-reproduce bug.</p>

<p><strong>How it works:</strong> the parser walks each line character by character tracking whether it's currently inside quotes, only treating a comma as a field separator outside them — a plain <code>line.split(',')</code> would incorrectly split a quoted field like "Reyes, Dana" into two columns. <h2>9. Bootstrap Rate-Limited Action Button</h2>

<p>A genuine sliding-window rate limiter on a "Send invite" button — the first several clicks fire instantly, and only exceeding the limit starts a live, accurately-recomputed countdown.</p>

<iframe src="https://fwdtools.com/ui-snippets/bootstrap-rate-limited-action-button/embed/" style="width:100%;height:400px;border:0;border-radius:10px;overflow:hidden;" loading="lazy" title="Bootstrap Rate-Limited Action Button — Free HTML CSS JS Snippet by FWD Tools"></iframe>

<p><strong>How it works:</strong> click timestamps are recorded and pruned against a rolling window, so the button only blocks once the real limit has genuinely been reached within that window — not on every click equally, the way a flat cooldown would. One function returns the exact milliseconds until the oldest click ages out, read by both the click handler and the countdown display, so they can never disagree. The countdown recomputes from real timestamps on every 250ms tick rather than decrementing a stored number, staying accurate even through background-tab timer throttling.</p>

<p><strong>Best for:</strong> invite, resend, and notification-sending buttons where a genuine burst should be allowed before anything blocks. <strong>Tip:</strong> this mirrors how a real API's sliding-window rate limit and 429 response actually behaves, not a naive per-click delay.</p>

<h2>10. Bootstrap Drag-to-Reorder List</h2>

<p>A real native HTML5 drag-and-drop reorderable list — a live rank number per row, a clear drop-target indicator, and array splicing that keeps order exactly right.</p>

<iframe src="https://fwdtools.com/ui-snippets/bootstrap-drag-to-reorder-list/embed/" style="width:100%;height:400px;border:0;border-radius:10px;overflow:hidden;" loading="lazy" title="Bootstrap Drag-to-Reorder List — Free HTML CSS JS Snippet by FWD Tools"></iframe>

<p><strong>How it works:</strong> this uses the browser's genuine native Drag and Drop API — <code>draggable="true"</code> plus <code>dragstart</code>/<code>dragover</code>/<code>drop</code> — the same approach this collection's kanban board uses for moving cards between columns. The one line that's easy to leave out and silently breaks everything is <code>e.preventDefault()</code> inside <code>dragover</code>; without it the browser refuses the drop entirely and no <code>drop</code> event ever fires. The reorder itself is a real array splice-out/splice-in, so the visible rank numbers are always the list's true current order, never a purely visual DOM shuffle disconnected from the data.</p>

<p><strong>Best for:</strong> priority lists, custom sort preferences, and dashboard widget ordering. <strong>Tip:</strong> native HTML5 drag-and-drop has inconsistent support on mobile touch browsers — pair with a Pointer Events fallback for a production implementation targeting touch devices.</p>

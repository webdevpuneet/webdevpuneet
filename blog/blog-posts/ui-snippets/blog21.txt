<p><strong>How it works:</strong> WPM uses the standard typing-test convention that one "word" equals five characters including spaces — <code>words = typed.length / 5</code>, then <code>wpm = Math.round((typed.length / 5) / (elapsedSeconds / 60))</code> — which normalises scoring across sentences with different average word lengths instead of counting actual word boundaries. The timer deliberately does not start on page load: it starts on the very first <code>input</code> event via a null-check on <code>startTime</code>, so time spent reading the prompt before you start typing never counts against you. A <code>setInterval</code> running every 100ms recalculates WPM, accuracy, and elapsed time continuously so the numbers update smoothly rather than jumping only on keystrokes.</p>

<p><strong>Best for:</strong> keyboarding-practice sites, recruiting pages for typing-heavy roles, and portfolio pieces that want to demonstrate real-time DOM diffing. <strong>Tip:</strong> the character-diffing and timing logic are cleanly separated from rendering, which makes this a good base to extend into a fixed-duration 60-second mode.</p>

<h2>2. Reaction Time Tester</h2>

<p>Wait for the panel to turn green, then click as fast as you can — click too early and it's a "Too soon!" fail, not a valid time.</p>

<iframe src="https://fwdtools.com/ui-snippets/reaction-time-tester/embed/" style="width:100%;height:560px;border:0;border-radius:10px;overflow:hidden;" loading="lazy" title="Reaction Time Tester Game — Free HTML CSS JS Snippet by FWD Tools"></iframe>

<p><strong>How it works:</strong> if the wait before "go" were a fixed duration, users would learn to time their click by rhythm instead of genuinely reacting. <code>randomDelay()</code> returns <code>1500 + Math.random() * 2500</code> — a random 1.5 to 4 second wait — passed into a cancellable <code>setTimeout</code>. The instant the panel flips green, <code>goTime = performance.now()</code> captures a high-resolution timestamp, and a click during the ready state computes <code>Math.round(performance.now() - goTime)</code> for the result in whole milliseconds. <code>performance.now()</code> is sub-millisecond precise and immune to system clock changes, which is exactly why browser profiling tools use it instead of <code>Date.now()</code>.</p>

<p><strong>Best for:</strong> neuroscience/cognitive-testing demo sites, "test your reflexes" landing pages, and as a teaching example for correct browser timing APIs. <strong>Tip:</strong> the cancellable timeout is the important detail — without it, a stray "go" state can fire after the round already ended in a too-soon failure.</p>

<iframe src="https://fwdtools.com/ui-snippets/simon-sequence-game/embed/" style="width:100%;height:560px;border:0;border-radius:10px;overflow:hidden;" loading="lazy" title="Simon Says Colour Sequence Game — Free HTML CSS JS Snippet by FWD Tools"></iframe>

<p><strong>How it works:</strong> the whole game state is one growing array, <code>sequence</code>, which gains a new random colour from <code>COLORS = ['red', 'green', 'blue', 'yellow']</code> every round. Rather than chaining <code>setTimeout</code> callbacks — unreadable once you're flashing ten pads in order — each flash is wrapped in a Promise-returning <code>lightPad(color, duration)</code> helper, awaited one at a time inside an <code>async function playSequence()</code>: <code>for (let i = 0; i &lt; sequence.length; i++) { await lightPad(sequence[i], 480); }</code>. <p><strong>Best for:</strong> memory-training apps, waiting-room/kiosk entertainment, and as a clean reference for the async/await sequencing pattern itself, independent of the game. <strong>Tip:</strong> the promise-per-flash pattern here generalises to any UI that needs to play a scripted sequence of animations in order without a callback pyramid.</p>

<h2>5. Sliding Number Puzzle (15-Puzzle)</h2>

<p>The classic 4x4 sliding tile puzzle — shuffled a way that guarantees it's actually solvable, which is the detail most from-scratch implementations get wrong.</p>

<iframe src="https://fwdtools.com/ui-snippets/sliding-puzzle-game/embed/" style="width:100%;height:560px;border:0;border-radius:10px;overflow:hidden;" loading="lazy" title="Sliding Number Puzzle 15-Puzzle — Free HTML CSS JS Snippet by FWD Tools"></iframe>

<p><strong>How it works:</strong> a purely random permutation of 15 tiles is unsolvable roughly half the time — permutation parity makes solvability a real mathematical constraint, not a formality. <code>shuffleFromSolved()</code> sidesteps the problem entirely by starting from the solved board and replaying 250 random <em>legal</em> slides, which can never leave a solvable state. A subtler bug it also avoids: naively picking any random legal neighbor lets the blank tile bounce back and forth between the same two cells, producing a shuffle that looks busy but barely mixes the board. The snippet tracks <code>lastEmpty</code>, the blank's position before the previous move, and filters it out of the candidate list each iteration, forcing every step to make genuine progress.</p>

<p><strong>Best for:</strong> waiting-screen distractions, brain-teaser content sections, and as a teaching example of permutation parity in a genuinely visual, hands-on way. <strong>Tip:</strong> tiles animate with <code>transform: translate()</code> rather than layout properties, so the slide is a pure GPU-composited move with no reflow cost.</p>

<h2>6. Tic-Tac-Toe vs Computer</h2>

<p>A real opponent, not a random-move bot: it takes a winning move when one exists, blocks yours when you have one, and otherwise prefers the centre, then corners, then edges.</p>

<iframe src="https://fwdtools.com/ui-snippets/tic-tac-toe-game/embed/" style="width:100%;height:560px;border:0;border-radius:10px;overflow:hidden;" loading="lazy" title="Tic-Tac-Toe vs Computer — Free HTML CSS JS Snippet by FWD Tools"></iframe>

<p><strong>How it works:</strong> <code>computerMove()</code> runs a short, ordered heuristic chain instead of a full minimax search: first <code>findWinningMove('O')</code> checks whether the computer can win this turn and takes it immediately; if not, the same function is reused with the human's mark to check <code>findWinningMove('X')</code> and block it; if neither applies, it takes the centre cell if open, then a random open corner, then a random open edge. Reusing one <code>findWinningMove(mark)</code> function for both the "can I win" and "must I block" checks — just by swapping which mark it's called with — is what keeps the whole AI to a handful of lines instead of a full game-tree search, while still playing a genuinely competent, not-obviously-beatable game.</p>

<p><strong>Best for:</strong> any site that wants a quick, low-stakes interactive moment — pricing page easter eggs, loading-screen distractions, kids' educational sites. <strong>Tip:</strong> the win/block/centre/corner/edge heuristic ordering is a reusable pattern worth knowing even outside Tic-Tac-Toe — it's the classic "good enough without search" approach to simple perfect-information games.</p>

<h2>7. Word Guess Game (Wordle-Style)</h2>

<p>A 6x5 Wordle clone with correctly-implemented duplicate-letter scoring — the single detail that breaks nearly every from-scratch Wordle tutorial.</p>

<iframe src="https://fwdtools.com/ui-snippets/word-guess-game/embed/" style="width:100%;height:560px;border:0;border-radius:10px;overflow:hidden;" loading="lazy" title="Word Guess Game Wordle-Style — Free HTML CSS JS Snippet by FWD Tools"></iframe>

<p><strong>How it works:</strong> a naive scorer checks whether each guessed letter exists anywhere in the target and colours it yellow if so — which breaks the moment a letter repeats. Guess ERASE against target CRANE and a naive check marks both E's yellow, even though CRANE only has one E. <code>scoreGuess()</code> fixes this with two passes sharing one <code>consumed</code> tracking array: pass one marks every exact-position match green and immediately consumes that target index; pass two then searches for an <em>unconsumed</em> occurrence of each remaining letter via <code>targetLetters.findIndex((t, idx) => t === letter &amp;&amp; !consumed[idx])</code>, marking it yellow and consuming it if found. Because consumption is tracked per target-letter-index and shared across both passes, a target with exactly one E can only ever credit one guessed E — matching real Wordle behaviour exactly.</p>

<p><strong>Best for:</strong> word-game portfolio pieces, ESL/vocabulary-learning sites, and as a genuinely useful interview-prep or tutorial artifact — the CRANE/ERASE edge case is a well-known trap worth walking through concretely. <strong>Tip:</strong> if you're extending this, test any change against a target and guess that share exactly two of the same letter — that's where naive scoring silently breaks.</p>

<h2>8. Morse Code Translator &amp; Player</h2>

<p>Type text, watch it convert to dots and dashes live, then hear it played back as real audio at exactly the international Morse timing ratios.</p>

<iframe src="https://fwdtools.com/ui-snippets/morse-code-translator/embed/" style="width:100%;height:560px;border:0;border-radius:10px;overflow:hidden;" loading="lazy" title="Morse Code Translator and Player — Free HTML CSS JS Snippet by FWD Tools"></iframe>

<p><strong>How it works:</strong> Morse code is defined entirely by timing ratios, not any visual shape — a dot is 1 unit, a dash is 3 units, the gap within one character is 1 unit, between letters 3 units, between words 7 units. This snippet derives every duration from one <code>UNIT_MS</code> constant (<code>DOT = UNIT_MS</code>, <code>DASH = UNIT_MS * 3</code>, <code>LETTER_GAP = UNIT_MS * 3</code>, <code>WORD_GAP = UNIT_MS * 7</code>), so changing playback speed is a single-line edit that scales the entire rhythm proportionally. Audio comes from a real <code>OscillatorNode</code>/<code>GainNode</code> pair created fresh per beep (an oscillator is single-use — once stopped it can't restart), set to a 600Hz sine tone, with <code>oscillator.stop()</code> scheduled against the audio context's own high-resolution clock rather than a JavaScript timer, so playback timing never drifts.</p>

<p><strong>Best for:</strong> ham-radio and signals-history content, scouting/survival-skills educational sites, and as a genuinely interesting small scheduling problem to study if you've never scheduled audio against an <code>AudioContext</code> clock before. <strong>Tip:</strong> the <code>AudioContext</code> is created lazily on first user interaction specifically to respect browser autoplay policies, which require an audio context to originate from a real user gesture.</p>

<h2>9. Virtual Piano Keyboard</h2>

<p>A real playable piano — click a key or press the mapped computer key, and hear the actual musically-correct note, not a generic beep.</p>

<iframe src="https://fwdtools.com/ui-snippets/virtual-piano-keys/embed/" style="width:100%;height:560px;border:0;border-radius:10px;overflow:hidden;" loading="lazy" title="Virtual Piano Keyboard — Free HTML CSS JS Snippet by FWD Tools"></iframe>

<p><strong>How it works:</strong> every key carries a real equal-tempered frequency (C4 = 261.63 Hz, up through B4 = 493.88 Hz), computed from the standard 12-tone equal temperament formula <code>freq = 440 * 2^((n-49)/12)</code> where A4 = 440 Hz. Pressing a key builds an <code>OscillatorNode</code> set to <code>type: 'triangle'</code> — a softer, more piano-like timbre than the harsh default sine wave — routed through a <code>GainNode</code> implementing a real attack/decay envelope: <code>linearRampToValueAtTime</code> ramps volume up over 20ms to avoid the audible "click" a hard volume jump causes, then an exponential ramp eases into sustain. Releasing the key ramps gain back down over 400ms before calling <code>osc.stop()</code>, producing a natural decay instead of an abrupt cutoff. The black keys are absolutely positioned overlapping the white keys, exactly like a real keyboard layout.</p>

<p><strong>Best for:</strong> music-education sites, a reference implementation for anyone learning <code>AudioContext</code>/<code>OscillatorNode</code>/<code>GainNode</code> envelope shaping for the first time, and as a base for interval-recognition or chord-building quiz tools. <strong>Tip:</strong> every key's <code>data-freq</code> attribute is copy-pasteable — it's a ready reference for converting note names to playback frequency in any other audio project.</p>
